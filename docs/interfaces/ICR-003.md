# ICR-003: chaos indicator (shadow particle and MEGNO)
Requested by: A3  Date: 2026-11-02
Status: Accepted by A0 2026-11-02; AJ approved in the Claude Code session.

## What

All changes are additive. A run without the new config table behaves and costs as before.

- Config: optional table `[diagnostics.chaos]` with `method = "shadow"`, `offset_km` (> 0) and `renorm_steps` (integer >= 1). `RunConfig` gets `diagnostics: Option<DiagnosticsConfig>` with `#[serde(default)]`. Old config files parse unchanged. When the table is absent, a backend allocates no extra memory and does no extra work.
- Trait: `Backend::chaos(&mut self) -> Result<Option<ChaosReport>>` with a default body that returns `Ok(None)`. Existing backends compile unchanged.
- `ChaosReport` (in `fring-model`): `time_s`, `n_renorm`, and per particle (particle order, same order as `Particles`): `ftle_per_s`, `log_growth` (L), `megno_mean` (mean of Y), `flags`.
- `fring-run` writes `chaos.csv` at the end of the run: `id, a0_km, lambda_rel_prometheus_deg, ftle_per_day, log_growth, megno_mean, flags`. It adds a `chaos` field to `meta.json` (settings of the indicator). Both are additive to snapshot format v1.
- RNG: a new stream `Stream::CHAOS_SHADOW = Stream(3)` for the direction of the initial shadow offset.
- Definitions (ADR 0008): the shadow starts at the particle position plus `offset_km` in a random direction (position only, zero velocity offset). At every global step number that is a multiple of `renorm_steps` (K), the backend measures the position separation d, adds l = ln(d / d0) to the sums, and moves the shadow back to the separation d0 along the same 6D direction. MEGNO is built from l with the discrete formula in ADR 0008.

## Why

PLAN 7.7 and task G3 need a chaos indicator per test particle on the GPU and the CPU, and task A1-ANALYSIS (A8) needs it for the chaos map. A trait method with a default body, an optional table and a new file keep every other role unaffected. a-diffusion is not part of this ICR: A8 computes it from the frames.

## Roles affected

- A0: `fring-model` (config, trait, report type, `physics/chaos.rs`, RNG stream). A0 reviews.
- A2: `CpuBackend` implements `chaos()`.
- A3: `GpuBackend` implements `chaos()`.
- A5: `fring-run` and `fring-io` write `chaos.csv` and the `meta.json` field. A0 delegated these edits to A3 for this task.
- A6, A7: none. A8: reads `chaos.csv`.

## Migration

None. `RunConfig` struct literals in tests get `diagnostics: None`.
