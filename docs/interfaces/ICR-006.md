# ICR-006: dropped particles in `GpuStepper` (unbound orbit, or inside a moon)
Requested by: A0 (for W2-DROP-GPU and W2-DROP, AJ request)  Date: 2026-11-02
Status: Accepted by A0 2026-11-02. AJ chose the scope (GPU stepper and web only), the rule (unbound orbit, and also inside a moon's radius) and that the work blocks gate G3, in the Claude Code session.

## What

With the moon-radius rule off (the default), the change is additive: `GpuBackend`, `fring-run`, `fring-bench` and the CPU reference keep their behaviour and their results, bit for bit.

1. **A drop reason for each particle, in the status buffer.** The status buffer (binding 4 of the step kernels, `GpuStepper::status_buffer()`) grows from 1 to `8 + cap` `u32` words. Its layout becomes part of this interface:
   - word 0: the smallest index of a dropped particle, or `u32::MAX` (`NO_FAILURE`) if none. This is the meaning of today's flag, so `GpuBackend` still reads only word 0 and still returns an error.
   - word 1: the number of particles dropped for an unbound or invalid orbit.
   - words 2 to 7: the number of particles dropped inside moon k = 0 to 5 (the moon order of the `System`).
   - word `8 + i`: the drop reason of particle i: 0 live, 1 unbound or invalid orbit, `2 + k` inside moon k.
   The web projection reads these words as `array<u32>` (read-only). A `System` with more than 6 moons and the radius rule on is a `Config` error.
2. **A dropped particle is frozen and costs almost nothing.** The step kernels (modes D and Dp) return at once for a particle whose reason is not 0: no load, no step, no store. Its state stays as last stored, which is the state at the start of the block in which it was dropped. A particle that fails in a block is not stored (as today); its own thread sets its reason and increments the matching count once, and `atomicMin` updates word 0. This also removes a fault of today's kernels: a failed particle is not stored, but the time goes on, so in the next block it starts again from an old state at the wrong time.
3. **Moon-radius rule (opt-in, default off).** `GpuStepper` gets a way to switch it on with one radius per moon, in km (A3 proposes the API in the plan round; for example a constructor argument or a setter before the first step). The rule: for each drift between two kicks, take the particle's position relative to moon k at the two kick times, interpolate linearly between them, and find the minimum distance. If it is less than the moon's radius, the particle is dropped with reason `2 + k`. Every drift is checked, also the one across a block boundary, or the handoff gives the fraction of drifts that are not checked. The radii are the mean radii `radius_km` in `params/moons.toml` (the moons are taken as spheres; cited in `params/sources.md`).
   - Why linear interpolation: relative to Prometheus, a ring particle moves about (3/2) n Δa = 1.5 x 1.17e-4 s⁻¹ x 840 km = 0.15 km/s, so about 53 km in one 360 s step. The moon is about 86 km across, so a check at the kick times only would miss many passes. Over 360 s the relative path is almost straight: 360 s is about 4 % of 1/n = 8,500 s.
4. **Rust twin and tests.** The segment test has a Rust twin and a comparison test (AGENTS.md, Precision). Native GPU tests (marked `#[ignore]`):
   - a particle that crosses Prometheus between two kicks (both kick positions outside the radius) is dropped with reason `2 + k`, in the right block;
   - a particle that passes at radius + 1 km is not dropped;
   - a particle with an unbound orbit is dropped with reason 1;
   - the other particles are bit for bit the same as in a run in which no particle is dropped;
   - the state of a dropped particle does not change in later blocks;
   - the counts and word 0 are correct;
   - with the rule off, the existing `GpuBackend` and `GpuStepper` tests pass unchanged.
   If the change touches double-single arithmetic, the test uses low words that are not zero (M24).
5. **`fring-web`** (W2-DROP) switches the rule on with the radii from `params/moons.toml`, reads words 0 to 7 with its small read-back, hides dropped particles in the projection, and lets the run go on.

The Rust twin lives in `fring-gpu` for now. E1 moves it to `fring-model/src/physics/` when the CPU reference uses the rule.

## Why

AJ (2026-11-02): in some web runs one failed particle stops the whole run ("a particle failed (index i); reset to continue"). A particle fails when its orbit about Saturn becomes unbound (alpha = 2/r - v²/GM <= 0). At r = 140,000 km, v_circ = 16.5 km/s and v_esc = 23.3 km/s, so one kick must give at least 6.8 km/s. A 360 s kick from Prometheus (GM = 0.01071 km³ s⁻²) gives GM h / d², so d <= sqrt(0.01071 x 360 / 6.8) = 0.75 km from the moon's centre (Pandora: 0.70 km). Each failure is therefore a pass deep inside a moon (mean radius 43 km and 41 km): in reality, a collision. Passes at 10 to 43 km get a kick of only 0.04 to 0.002 km/s and are not seen today. AJ: drop the particle and stop simulating it; also drop particles that come inside a moon's radius.
