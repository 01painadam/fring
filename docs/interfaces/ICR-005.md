# ICR-005: `fring-gpu` in the browser (non-blocking stepper and self-test)
Requested by: A0 (for W2)  Date: 2026-11-02
Status: Accepted by A0 2026-11-02; AJ approved in the Claude Code session.

## What

All changes are additive for native code. `GpuBackend`, `fring-run` and `fring-bench` keep their API and their results.

1. **Native-only items, by target.** `pollster` and `rayon` move to `[target.'cfg(not(target_arch = "wasm32"))'.dependencies]` in `crates/fring-gpu/Cargo.toml`. Every item that blocks or reads the clock gets `#[cfg(not(target_arch = "wasm32"))]`: `Gpu::new`, `Gpu::run`, `Kernel::run`, `probe::self_test`, `probe::run_probe`, `spike_gpu`, `WhKernels::new`, `WhKernels::apply`, the `backend` module (`GpuBackend`) and `startup_check`. A web build cannot call them, so it cannot hang on a blocking wait.
2. **`Gpu::from_parts(device, queue, info, limits) -> Gpu`.** Wraps a device that the caller opened. The browser opens it asynchronously, with an adapter that is compatible with the canvas.
3. **`WhKernels::compile(gpu, workgroup) -> WhKernels`.** Compiles the kernels with no self-test. `WhKernels::new` becomes `self_test(gpu)?` followed by `compile`, with no change in behaviour.
4. **Two-phase self-test, `probe::SelfTest`.**
   - `SelfTest::submit(gpu: &Gpu) -> SelfTest` writes the inputs, encodes the core checks of `self_test` in one submission, copies the outputs to a `MAP_READ` buffer and calls `map_async`.
   - `SelfTest::poll(&mut self) -> Option<Result<()>>` returns `None` while the map is pending. After that, it returns the same result as `self_test`, with the same checks against the Rust twins and the same error text.
   - The blocking `self_test` becomes `submit`, then `device.poll(wait)`, then `poll`. So both paths use one set of checks.
5. **`GpuStepper`: the non-blocking core of `GpuBackend`.**
   - `GpuStepper::new(gpu: &Gpu, kernels: &WhKernels, system: &System, init: &InitialState, step_s: f64, block_steps: usize, chaos: Option<ChaosConfig>) -> Result<Self>` makes the buffers and uploads the constants and the states. It does not block.
   - `encode_steps(&mut self, encoder: &mut wgpu::CommandEncoder, n_steps: u64) -> Result<()>` fills the moon kick table on the host, writes it with `queue.write_buffer` and records the dispatches (the same blocks, the same chaos renormalisation steps as `GpuBackend::step`). The caller submits.
   - `time_s()`, `len()`, `capacity()`, `state_buffer() -> &wgpu::Buffer` and `status_buffer() -> &wgpu::Buffer`. The state buffer has usage `STORAGE | COPY_SRC`. Its layout is documented as part of this interface: 6 planes (x, y, z, vx, vy, vz; inertial, km and km/s); particle `i` of plane `c` is the double-single pair at f32 words `2 (c cap + i)` (high) and `2 (c cap + i) + 1` (low).
   - `GpuBackend` keeps a `GpuStepper` and adds the blocking parts: the ring of slots with `poll`, the snapshot readback (with rayon), the failure flag and `startup_check`.
6. **`fring_model::params::ring_from_toml_str(text) -> Result<RingParams>`** (A0). It reads `[core]` and `[targets]` of `params/ring.toml`, like `saturn_from_toml_str`. `fring-web` then removes its own parser.
7. **CI** (A0): `cargo check -p fring-gpu --target wasm32-unknown-unknown`.

## Why

W2 runs the production WH kernels (`shaders/wh.wgsl`, double-single, ADR 0006) in the browser. Today `fring-gpu` compiles for wasm32, but it cannot run there:

- `pollster::block_on` and `device.poll(wait)` block. A browser does not let the main thread block, and a `map_async` callback runs only after the page returns to the event loop. `Gpu::new`, `WhKernels::new` (through the self-test) and every readback would hang.
- `std::time::Instant::now` panics on `wasm32-unknown-unknown`.
- `GpuBackend` unpacks the snapshot with rayon. Plain wasm32 has no threads.

The self-test must run in the browser too. Chrome (Dawn) and Safari (WebKit) compile WGSL to Metal with their own compiler options, and we do not know whether they let the compiler re-associate the guarded sums. The two-phase form fits the animation loop: the page calls `poll` once per frame until it gets a result. If the self-test fails, W2 shows a message and does not start the integrator.

A shaders-only module (W2 copies the WGSL and writes its own host code) was rejected: the constants, the kick table, the block logic and the state layout would exist twice, and the Rust-twin tests would not cover the web copy. A `native` Cargo feature was rejected: Cargo merges features across the workspace, so a web build could get the blocking code back by mistake. A target cfg cannot.

## A0 amendment (W2-GPU plan round)

2026-11-02, A0. Three small additions found by A3 in the plan round. They do not change native behaviour.

1. `GpuStepper::new` takes one more argument, `mode: wh::Mode`, after `block_steps`: `new(gpu, kernels, system, init, step_s, block_steps, mode, chaos)`. The entry point of the block kernel depends on it (`Mode::entry`), and `GpuBackend` passes `Options::mode`.
2. `GpuBackend::stepper() -> &GpuStepper` (read-only). It is for the bit-for-bit tests and for inspection.
3. `encode_steps` gives each block of one call its own slot (kick table and control buffer). The slot list grows to the largest number of blocks in one call and does not shrink. The caller must submit the encoder before the next `encode_steps`. Reason: `queue.write_buffer` takes effect at the next `submit`, so blocks that share a slot in one encoder would all see the last write.
