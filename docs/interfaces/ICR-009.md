# ICR-009: collision config, collision diagnostics and the `fring-collide` dependency
Requested by: A4 (task K1)  Date: 2026-11-07
Status: accepted with amendments (A0, 2026-11-07). AJ chose box cells with three sizes (Q2) and `every_steps` (Q3) on 2026-11-07 (SPEC section 13).

## What

1. `crates/fring-model/src/config.rs`, `Collisions::Stochastic`: replace `cell_size_km` with three sizes and add the cadence (SPEC 5.1, 7):

   ```toml
   [collisions]
   model = "stochastic"
   particle_radius_km = 1.0e-5
   weight = 8.0e8
   cell_radial_km = 0.05       # L_x
   cell_azimuthal_km = 10.0    # L_y (adjusted so that whole cells fill the domain)
   cell_vertical_km = 0.04     # L_z
   every_steps = 1             # collision step every k integrator steps (default 1)

   [collisions.restitution]
   law = "constant"
   epsilon = 0.5
   ```

   Validation: the three sizes > 0, `every_steps` ≥ 1. `HardSphere` does not change (it always acts every step).

2. `crates/fring-model/src/backend.rs`, `StepStats`: add `pub collision: CollisionStats` (default zero), with:

   | Field | Meaning |
   |---|---|
   | `collisions: u64` | accepted pairs (equal to `collisions_since_last`, which stays) |
   | `energy_loss_km2_s2: f64` | Σ ¼ (1 − ε²) gₙ², per unit superparticle mass |
   | `candidates: u64` | stochastic: candidate pairs tested |
   | `occupied_cells: u64` | stochastic: Σ over collision steps |
   | `occupancy_sum: u64`, `occupancy_sq_sum: u64` | stochastic: Σ N_c and Σ N_c² over cells and steps |
   | `lonely_particles: u64` | stochastic: Σ of particles in cells with N_c < 2 |
   | `overfull_cells: u64` | stochastic: cells with W σ g_max Δt / V_c > 1 |
   | `deep_collisions: u64` | hard-sphere: overlap depth > 0.2 s |

   All fields count since the previous call to `Backend::stats`.

3. Workspace: `fring-collide` becomes a dependency of `fring-cpu` (K2, K3) and `fring-gpu` (K5, for the Rust twins). `fring-collide` depends only on `fring-model`, so it builds for wasm32; CI adds `cargo check -p fring-collide --target wasm32-unknown-unknown`.

## Why

- One cube size forces L_y = L_x. SPEC section 10: the core needs L_x ≈ 50 m but allows L_y ≈ 10 km, and with cubes of 50 m a 5° arc with 10⁶ superparticles has an occupancy of about 0.5, too low for the NTC method.
- `every_steps` lets B2 trade cost against accuracy (SPEC section 7: 0.032 collisions per particle per step at τ = 0.3, so k = 2 or 3 stays under the 0.1 limit).
- The diagnostics are the evidence for the limits of SPEC 5.6 and 8, and the energy loss is needed for the energy budget of a collisional run.

## Roles affected

- A0: `config.rs`, `backend.rs`, the config tests, ADR 0001 (it shows the old field), CI.
- A5: `fring-run` writes the new `StepStats` fields to `stats.csv` (and `docs/snapshot-format.md` lists the columns, A0).
- A2, A3, A4: use the new fields in K2, K3, K5.

## Migration

No run config uses `stochastic` yet (only `crates/fring-model/tests/config.rs` and ADR 0001). Change the struct and the tests in one PR. `StepStats` uses `..Default::default()`, so existing backends compile unchanged.

## A0 decision

Accepted with amendments, 2026-11-07 (review: PR #38). The implementation follows the text above with these changes:

- **A1.** No `collisions` field in `CollisionStats`. `StepStats::collisions_since_last` stays the only count of accepted pairs, so two copies of one count cannot disagree.
- **A2.** Add `gmax_exceeded: u64` to `CollisionStats`: stochastic, candidates with |g| > g_max (SPEC 5.3 after the K1 review: such a candidate is accepted with probability 1).
- **A3.** Migration, more files: `crates/fring-io/tests/stats.rs` (4 literals) and `crates/fring-io/tests/run_dir.rs` (1 literal) set every field of `StepStats` without `..Default::default()`, so they must change in the same PR. `apps/fring-run/tests/run.rs` uses `cell_size_km` and expects the "not implemented ... K1" error, which becomes K2. These are A5 files: the implementation PR changes them, and A5 reviews.
