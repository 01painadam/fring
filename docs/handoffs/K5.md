## How it works (for the wiring task)
```rust
let collider = GpuCollider::new(&gpu, stepper.state_buffer(), binner.sorted_buffer(), binner.sorted_keys_buffer(),
                                n, stepper.capacity(), &field, CollideParams { .. }, lx * ly * lz, /* box_mode */ false)?;
stepper.encode_steps(&mut enc, k)?;
binner.encode(&mut enc, stepper.time_s());
collider.encode(&mut enc, steps_total_after, every_steps as f64 * step_s);   // same encoder, one submit
let tally = collider.read_tally()?;                                           // later: when stats are read; Err = cell with 32,767 candidates
```
- `volume` = L_x L_y L_z with the adjusted L_y of `BinGeometry`. `step` is the step count after the integrator step (SPEC 5.5).
- `read_tally` reads 16 words, so it can be called at the stats interval; the integer counters then hold the last pass only (cleared in each pass). Add them up on the host (`Tally += `).
- Exact between GPU and twin or CPU: Philox words, runs and N_c, smallest id, i and j, number of candidates, the occupancy sums. With tolerance: acceptance, normal, velocity changes (f32).
- An overfull cell (32,767 candidates or more) is skipped and counted; `read_tally` returns an error. The CPU stops at the first such cell; the GPU has changed the other cells before the host sees the error. The run stops either way (A0, 2026-11-08). Comment in `cell.wgsl` and `collide.rs`.
- The kernel needs 6 storage buffers (the WebGPU default is 8) and `ds.wgsl` with `ds_one` set (done in the entry points); the DS self-test must have run.

## Open questions / blockers
- None for K5. ICR-010 is accepted.
- `cell.wgsl` runs one thread per cell and starts a thread for every sorted position (most return at once). Not measured for cost; B2 (A5) measures it with the bin pass. A compaction of the run starts is the first thing to try if it matters.
- Only box tests and the full-ring chain are tested. The arc domain uses the same runs (ARC-CELLS-GPU), but no test runs the collider on an arc.

## Decisions made (link ADRs)
- A0 and AJ 2026-11-08: ICR-010 accepted; T8a GPU bound 1e-11 km/s (proposed 1e-8). T6 energy and T8b as proposed.
- A4: f32 uniforms `u01_f32` of one word per number (SPEC 5.5): word 0 rounds M; draw 1+2k: words 0, 1 give i, j and word 2 the acceptance; draw 2+2k: words 0 and 2 give u1, u2. The CPU uses `u01_f64` of word pairs, so the acceptance and the geometry are not the same numbers on the two backends.
- A4: the energy loss is summed in double-single in a fixed order (two passes), the integer counters with atomics, so the tally and the state are bit-identical between runs (K1-T9).
