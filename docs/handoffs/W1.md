## Goal and acceptance criteria
`fring-web` scaffold: Rust to wasm32 with wgpu (WebGPU), renders particles in the rotating frame. Done when: it runs in current Chrome and Safari (PLAN section 9, phase 3).

## Done
- Dependencies (AJ, 2026-11-02), wasm32 target only: wasm-bindgen 0.2.130, wasm-bindgen-futures 0.4.80, web-sys 0.3.107, console_error_panic_hook 0.1.7, wgpu 30.0.1 (workspace). `serde` and `toml` (already workspace crates) are used to read `params/ring.toml`.
- `src/scene.rs`: 20 000 particles, analytic first-order epicycles (`epicycle_state`), turned into the frame that rotates at n0 (`inertial_to_rotating`). Moons are schematic circular orbits. Host tests.
- `src/view.rs`: pan and zoom camera, `ViewTransform` (rotating frame to view plane). Host tests.
- `src/web.rs` (wasm32 only) and `shaders/points.wgsl`: wgpu pipeline, instanced discs.
- `index.html`: controls (pause, speed, preset, view, reset view), mouse pan and zoom, message when WebGPU is missing.
- AJ review (2026-11-02), done by the main session as A7:
  - "Moons and the outer half of the ring move retrograde": correct for the frame that turns at n0. Material outside a0 has n < n0 and falls behind (clockwise); inside, it moves ahead. Schematic radii: Prometheus 139 160 km (a0 - 1 062 km), +6.7 deg/day; Pandora 142 228 km (a0 + 2 006 km), -12.3 deg/day. New test `prometheus_moves_ahead_and_pandora_falls_behind_in_the_ring_view`; the page note now explains the directions.
  - New "View" select: inertial (fixed camera, the default, AJ), rotating (camera turns with the core; was "ring view", renamed by AJ), or centred on Prometheus or Pandora. The inertial view turns the rotating-frame positions back by n0 t with the same f64 angle as `inertial_to_rotating`, so the turns cancel to rounding (test: 1e-8 km up to about 100 years). A moon view turns with the moon: Saturn straight down, orbital motion to the left, seen from the north (no mirror). The transform runs in f64 before the eye subtraction; the precision test covers the moon view.
- `scripts/build.sh`: build to `apps/fring-web/dist/`. wasm size 690 385 bytes.
- No `unsafe_code` lint fired with wasm-bindgen, so there is no ADR 0009 and no `allow`.

Browser steps for AJ (Safari 26) and A0 (Chrome), at http://localhost:8080:
1. The page opens with no error box. The footer line of the panel shows "GPU: <name>".
2. Dark window with a thin blue circle (the F ring, radius 140 222 km), a dull disc in the centre (Saturn) and two coloured dots on slightly different radii: orange Prometheus, green Pandora. The default view is inertial: everything goes round anticlockwise, the core once per 14.85 h (2.5 s at 6 h/s). In "Rotating (camera turns with the core)" the core stays still, Prometheus moves anticlockwise (+6.7 deg/day) and Pandora clockwise (-12.3 deg/day).
3. The readout shows t in days and the view width in km. t grows (default 6 h per second).
4. Scroll wheel zooms about the cursor. Zoom to a width of about 2000 km at the ring: you see 20 000 particles' local density as a thin band. Drag moves the view.
5. Pause/Play, Speed slider (0.1 h/s to 250 h/s), "Reset view" resets the camera of the current view, "Band (circular)" switches the particles and sets t = 0.
6. Check the browser console for errors. Expected: none.
7. Missing WebGPU: in Chrome open `chrome://flags`, or test in a browser without WebGPU. Expected: a full-window message "This page needs WebGPU".
8. View "On Prometheus": the orange dot stays at the centre, Saturn is off-screen straight down, the ring core is about 1 060 km above the moon and drifts to the right (it falls behind Prometheus). "On Pandora": the green dot at the centre, the core about 2 000 km below it, drifting to the left. Pan and zoom work in both; "Reset view" goes back to the moon. With the Core preset the core also moves up and down by about 330 km (a0 e) once per orbit (14.85 h, so every 2.5 s at 6 h/s): the aligned eccentric ring turns past the moon.
Check Safari for: canvas not blank, frame rate smooth at 20 000 particles (the CPU computes all positions each frame, about 20 000 epicycles), resize works, wheel zoom does not scroll the page.

## Open questions / blockers
- No browser check done by A7 (see Next step).
- Precision method (decision, per A0 advice): positions are computed in f64 on the host and the camera centre (the "eye") is subtracted in f64 before rounding to f32. No trig in the shader, exact to about 1e-4 pixel at any zoom (tested in `camera_relative_f32_error_is_below_a_pixel_fraction`). Local polar coordinates were rejected: they need atan2 in the shader or on the host and give no better precision. W2 can do the same on the GPU with a double-single subtraction.
- A0 note: the doc comment of `FrameConfig` in `crates/fring-model/src/config.rs` says "J2 and J4 included", but `reference_mean_motion` uses `frequencies`, which includes J6. So n0 is the exact n at a0, and a circular orbit at a0 is at rest in the rotating frame (test tolerance 1e-6 km, derived from rounding: 1e-16 * 1.2e3 rad * 1.4e5 km = 2e-8 km).
- Core preset width: sigma(a) = `dust_strand_width_min_km` (10 km) from `params/ring.toml`, a display choice. Band preset: a0 +- a0 e.
- Touch pinch zoom is not implemented (mouse wheel and drag only).

## Decisions made (link ADRs)
- Build with `scripts/build.sh` (D2). Profile `wasm-release` in the root `Cargo.toml` (`[profile.release]` unchanged).
- Vertex instance buffer (not a storage buffer) for the draw data: more portable. W2 can give it the usage STORAGE | VERTEX and write it from a compute shader.
