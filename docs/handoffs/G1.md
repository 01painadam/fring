# G1: GPU precision spike
Role: A3  Branch: ws/a3-g1  Status: doing
Updated: 2026-11-01

## Goal and acceptance criteria
From `docs/PLAN.md` section 9 and gate G1: compare precision options for the Wisdom-Holman integrator (ADR 0003) on one circular and one eccentric orbit over 10⁴ orbits. The options of the plan, adapted to the Kepler drift: (a) f32, (b) f32 with double-single (DS) accumulation, (c) DS throughout, plus mixed options ((b+) and (d), see the plan in the PR description). *Done when:* ADR 0006 picks the cheapest option that meets PLAN section 10 (GPU against CPU, 10³ orbits, non-chaotic: Δa < 0.01 km, phase < 10⁻⁵ rad), and gives an explicit recommendation on GPU or CPU for the science runs.

A0 decisions (2026-11-01):
- wgpu and pollster approved.
- Test against PLAN section 10 as written. ADR 0006 also shows each option's error next to the CPU's own error against the true orbit at the same step (2π · 10³ · 6.6 × 10⁻⁸ ≈ 4 × 10⁻⁴ rad at 10³ orbits, 150 steps per orbit).
- GPU for science runs only if the cheapest passing option is at least 3 times the CPU throughput (6.4 × 10⁷ particle-steps/s). Between 3 and 5 times: say so and list the extra GPU work (G2, G3, K5).
- Run the M4 probe first. If DS does not survive compilation, stop and report to A0.

## Probe result (Apple M4, Metal, 2^20 values per check)
- + and * are correctly rounded (0 failures). `fma` is fused and exact (0 failures). A plain `a*b - p` is not contracted.
- **Plain DS does not survive compilation.** TwoSum and Fast2Sum fail for every value with a non-zero error (925,090 of 2^20); Dekker's split fails for all. DS add, mul and div errors are about 4 × 10⁷ × 2⁻⁴⁸ (that is, f32 accuracy). Cause: wgpu-hal does not disable Metal fast math (`MTLCompileOptions` default), so the compiler re-associates `(a + b) - a` to `b`. naga has no option for this.
- **Work-around that works on the M4:** multiply the sums by a runtime 1.0 read from a uniform buffer (`two_sum_g`, `fast_two_sum_g`, or Fast2Sum after a branch-free magnitude sort). 0 failures in 2^20 for each; DS add 2.4 × 2⁻⁴⁸ and DS mul 3.4 × 2⁻⁴⁸ (theoretical bounds 3 and 4). Cost: 2 to 4 extra multiplications per TwoSum. Risk: a later compiler could see through it, so a GPU backend would need this probe as a self-test at start.
- Division: max 1.71 ULP, 28 % not correctly rounded. sqrt: max 1.73 ULP, 28 % not correctly rounded. 1/x: 0.71 ULP; inverseSqrt: 0.65 ULP.
- Built-in sin and cos on the M4: max absolute error 1.3 × 10⁻⁷ on [-π, π] (the WGSL bound is 2⁻¹¹ = 4.9 × 10⁻⁴); relative 1.9 × 10⁻⁷ on [-0.1, 0.1].
