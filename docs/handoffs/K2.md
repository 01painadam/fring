## How to call it (for K2-CPU, A2)
```rust
let field = SaturnField::from_params(..);          // already in CpuBackend
let n0 = reference_mean_motion(&field, a0);        // a0 = RunConfig.frame.reference_semi_major_axis_km
let domain = Domain::full_ring_from_config(&cfg.collisions, a0, n0).unwrap();   // once
let model = StochasticModel::from_config(&cfg.collisions, cfg.run.seed).unwrap(); // once
// every `every_steps` integrator steps, on the synchronised state:
let tally = model.collide_step(&domain, &field, t_s, steps_total_after, every_steps as f64 * step_s,
                               &ids, Some(&active), &mut state)?;   // state: &mut [[f64; 6]] = fring-cpu State
// tally.collisions -> StepStats::collisions_since_last; tally.stats -> StepStats::collision (sum with `+=`)
```
For rayon: `domain.build_cells(...)` once, then `model.process_cell_states(...)` per cell with one `CellScratch` per thread (it reads the state and writes the velocity changes to `scratch.delta_km_s`), then add the changes to `vx, vy, vz` serially. The result does not depend on the cell order. `fring-collide` has no rayon dependency.
Notes: `collide_step` allocates a `CellList` each call (an integer sort of the active particles); `ids` need not be sorted. `t_s` is the time since the epoch (`CpuBackend::time_s`), the same time that the rotating frame uses.

## Open questions / blockers
- Only the full ring is supported (phi0 = 0, D = 2 pi a0). `Domain` has `phi0_rad` and the grid has D, so D1 needs no API change.
- K1-T8b uses a test-only exact circular-orbit step (a particle on a circular orbit turns at v_circ(r)/r), because `fring_model::physics` has no exact circular drift; the leapfrog orbit differs from `circular_speed` by about 10^-3 relative, far above the 10^-12 km/s of the test. A comment in the test says so.
- T8b detail: with W = 10^14 the cold ring still has 41,206 collisions in 10 orbits, from the 10^-13 km/s rounding of the exact orbits; the largest peculiar velocity or difference to the run without collisions is 6.5 x 10^-13 km/s (limit 10^-12). Margin is 1.5, not large; it comes from the test's own orbit step.

## Decisions made (link ADRs)
- A4: `process_cell` works on peculiar velocities and returns the change per member; `collide_step` adds that change to the inertial velocity, so the 16.5 km/s part is never subtracted and added back (SPEC 12).
- A4: a candidate with g = 0 is counted as a candidate and skipped (no direction for the impact geometry).
- A4: an overfull cell (W sigma g_max dt / V_c > 1) is counted and still runs; only the 32,767-candidate limit is an error.
